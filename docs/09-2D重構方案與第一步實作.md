## 二、三個不可妥協的決策（與取捨）

### 1. 引擎不換：仍是 **Godot 4.7 Mono / C#**

理由：Core 是 C# net8.0，換引擎等於放棄「0 錯誤直接搬」這個最大優勢；
而且 `data/core.json`、`CFBP1` 藍圖、二進位存檔、四語字串表全部可以原樣沿用。
2D 內容改用 canvas 批次繪製（分層 + 區塊），效能目標與 3D 版一致。

### 2. 新增 `game2d/` 獨立專案，舊 3D 專案**一行都不動**

`game/` 是可發行的 0.7.1 成品；2D 版在旁邊長出來，風險隔離。
Core 用 MSBuild 的 `<Compile Include>` 連結 → **單一真相來源**，不存在「兩份 Core 各自漂移」的地獄。
代價：2D 版暫時不能自由修改 Core（改了會影響 3D 版）—— 在「Core 是凍結資產」的前提下這是優點。
要分叉時只要把這行換成指向本專案內的複本即可，一行切換。

### 3. 座標沿用 Core 的 `(X, Z)`，不做任何翻轉

| Core | 2D 螢幕 | 說明 |
| --- | --- | --- |
| `X`（+東） | `x` | 直接 |
| `Z`（+南） | `y` | 直接（3D 遺產的 Z 軸 = 2D 的縱軸） |
| `Dir.North` | `-y`（上） | 因 `Dirs.Dz(North) = -1` |
| 1 格 | 32 px | 世界單位 = 像素，縮放交給 `Camera2D.Zoom` |
| 座標範圍 | ±32760 | `SimWorld.Key` 是 16-bit 打包，超出會溢位 |

好處是渲染層與模擬層「講同一種語言」，不用在邊界轉來轉去（轉譯層是 bug 溫床）。

## 三、網格與區塊方案

- **區塊 = 32×32 格**（2 的冪 → 用位元運算取 `ChunkOf(t) = t >> 5`，負座標也正確）
- 區塊資料（`Chunk.cs`）：地形快取 4 個 byte 陣列（種類 / 礦種 / 豐富度 / 高度明暗）+ 建築鍵清單 + 傳送帶鍵清單
- **地形不存檔**：它是 seed 的純函式，區塊載入時重算（延續 Core「存檔 = 種子 + 增量」的原則）
- **串流**（`ChunkManager.cs`）：依相機視野 ±1 圈載入，每幀最多 3 個區塊（由中心向外排優先序）；
  卸載再多留一圈做遲滯，避免在邊界來回抖動

### 索引一致性的三層保險（這裡最容易長 bug）

渲染層需要「這個區塊裡有哪些建築/傳送帶」，但建築可能被三種方式改動：

1. **走管理器的放置/拆除** → `MarkTileChanged(x,z)` 立即重掃該區塊（1024 格 ×2 次字典查詢，加減都正確）
2. **蟲潮在模擬層直接刪建築**（`SimWorld` 不會通知任何人）→ 每 tick 用 `Count` 對帳，不一致才全量重建（O(N)，極少發生）
3. **讀檔 / 換星球**整批換內容 → `ResetAll()` 全清，讓區塊用新 seed 重生成

自我測試的 T4b / T4e / T4f 各鎖住一條；截圖測試還額外在真實執行期撞出「蟲把倉庫拆了」的狀況，
證明第 2 條對帳在實戰有效。

## 六、Step 2–4 路線圖

**Step 2（導入 Core）—— 實質已完成**：Core 已連結、0 錯誤、自我測試證明同一份模擬在新專案跑得動。
剩下的只是分叉決策：若 2D 版要改 Core，把 csproj 那一行 `Compile Include` 指向本專案內的複本。

**Step 3（2D 渲染精修與 UI/HUD）**
1. 移植 `ThemeFactory`（Microsoft YaHei 系統字型）→ 才能顯示中英日 CJK 介面
2. 建造工具：左鍵放置（傳送帶連續鋪）/ 右鍵拆除 / `R` 旋轉 / `Ctrl+滾輪` 配方 / `C` `V` 藍圖 → 全部走 `ChunkManager.MarkTileChanged`
3. 高辨識度精靈圖取代色塊；保留「進料藍 / 出貨綠」箭頭與帶面流動紋理
4. 右側資訊欄直接吃 `WorldGrid2D.DescribeTile`
5. 警告提示：`ChunkView2D` 已先畫出「出貨未接線」的紅點，升級成正式提示文字

**Step 4（存讀檔與藍圖）**
1. 移植 `SaveManager`（存檔槽 + session 記錄）
2. 藍圖字串匯入匯出 UI（`CFBP1` 編解碼已在 T5c 驗證）
3. 存讀檔後必須呼叫 `ChunkManager.ResetAll()`（seed 變了，地形要重算）

## 七、待決議題（要你拍板）

1. **2D 與 3D 是否長期並存？** 目前並存且共用 Core。若確定 2D 是唯一未來，可把 Core 搬到 `game2d/src/Core` 並讓 3D 版反向連結，或直接凍結 3D 版。
2. **地形 LOD**：現在縮到 0.35× 時，一個區塊仍畫滿 1024 格。要不要在低縮放改用 2×2 合併成一個色塊？
3. **礦脈視覺密度**：截圖顯示礦脈面積偏大（Core 的 `ResourceThreshold = 0.42` 造成的大片 blob）。這是「改 Core 數值」還是「只改 2D 表現」？傾向後者（避免動到模擬）。
4. **世界大小**：±32760 格（約 65k × 65k）由 Core 的 16-bit 打包決定。若想要更大地圖，得改 `SimWorld.Key`——那是動 Core，需先決定 2D/3D 是否共用。
