# 07 · 更新指南（怎麼持續改這款遊戲而不弄壞玩家存檔）

> 目標：你未來會一直更新。這份文件說明**哪些改動是安全的、哪些必須做遷移、以及怎麼發版**。

---

## 1. 發版流程（標準動作）

1. 改 `VERSION`（例如 `0.1.0` → `0.2.0`）
2. 同步 `game/project.godot` 的 `config/version="0.2.0"`
3. 在 `CHANGELOG.md` 最上面加一節
4. 打標籤推送：`git tag v0.2.0 && git push origin v0.2.0`
5. GitHub Actions（`.github/workflows/export.yml`）會自動：
   - 下載 Godot 4.7.2 (.NET) 與匯出模板
   - `--import` 資源後 `--export-release`
   - 把 `CoreFactory.exe` + `data_CoreFactory_windows_x86_64/` 附到 Release

手動打包（本機）：
```bash
cd game && dotnet build
cd .. && mkdir -p build
Godot_v4.7.2-stable_mono_win64.exe --headless --path game --import
Godot_v4.7.2-stable_mono_win64.exe --headless --path game --export-release "Windows Desktop" "$PWD/build/CoreFactory.exe"
```

**發布時 exe 與 `data_*` 資料夾必須一起發**（那個資料夾是 .NET 執行時，少了它遊戲起不來）。

---

## 2. 改平衡、加內容 → 改 JSON，不要改程式

`game/data/core.json` 是唯一的數值來源：傳送帶速度、採礦時間、發電量、砲塔參數、配方、建造成本、耗電。

玩家也可以自訂：`%APPDATA%\Godot\app_userdata\Core Factory Infinite Horizon\data\core.json`
（遊戲第一次啟動會自動建立，**更新遊戲不會蓋掉它**；只需寫你要改的欄位，其餘沿用內建。）

要新增物品/建築種類 → 那需要改程式（`ItemId` / `BuildingKind` 列舉），並在 `Localization.cs` 補上中英名稱。

---

## 3. 存檔相容規則（最重要）

- `SimWorld.SaveVersion` 是存檔格式版本。**任何欄位增刪都要 +1**。
- 讀檔時用 `if (version >= N)` 分支讀新欄位，舊存檔缺的欄位給預設值 → 舊存檔自動升級。
  （v2 → v3 就是這樣加入「研究等級」的，見 `SimWorld.LoadFrom`。）
- **不要改動既有欄位的寫入順序**，只能在尾部追加；順序一改，所有舊存檔全毀。
- `SimWorld.LoadFrom` 讀到不支援的版本會**明確報錯**，不會靜默失敗。

## 4. 藍圖相容規則

- 藍圖字串自帶版本（`CFBP1:`）。改格式請升 `Blueprint.FormatVersion`，並在 `TryDecode` 裡保留舊版解析分支。
- 玩家的藍圖存在剪貼簿/社群裡 —— 靜默失效等於把 UGC 生態清零。

## 5. 設定檔相容規則

- `Settings`（`user://settings.cfg`）使用「取值帶預設」的寫法：
  `cfg.GetValue("video", "quality", Quality)`，所以**新增設定項不會讓舊設定檔壞掉**。
- 新增設定時請同步：① `Settings` 欄位 + `Load/Save` ② `Menu.BuildSettings()` 的 UI ③ `Localization.cs` 的 key。

## 6. 安全 / 風險檢查清單（每次發版前）

- [ ] `dotnet build` 0 錯誤
- [ ] `tools/Bench` 全部測試通過（含存檔往返、藍圖解碼）
- [ ] `godot --headless --path game --quit-after 300` 無 ERROR
- [ ] 舊存檔能讀（拿上一個版本的 `.cf` 測一次）
- [ ] 新玩家第一次啟動：能建圖標、能看到主選單、能存檔
- [ ] 打包後 exe 能跑：`CoreFactory.exe --headless --quit-after 200`

## 7. 建議的更新節奏

| 類型 | 內容 | 風險 |
| --- | --- | --- |
| 熱修 | JSON 數值、文字 | 無（可隨時發） |
| 小版 | 新配方、新威脅參數、UI 調整 | 低（存檔不動） |
| 中版 | 新機器、新邏輯節點、新星球 | 中（存檔 +1 版、藍圖可能 +1 版） |
| 大版 | 改存檔結構、改核心模擬模型 | 高（務必寫遷移 + 實測舊存檔） |
