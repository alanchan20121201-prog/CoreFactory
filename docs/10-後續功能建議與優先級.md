# 10 · 後續功能建議與優先級（v0.2.0 之後要做什麼）

> 撰寫角色：設計策略（遊戲系統與經濟設計）
> 適用版本：**2D 版 v0.2.0**（`game2d/`）
> 產出性質：**建議書，不含任何程式改動**。本文件不動 `game2d/src/` 任何一行。
> 唯一準則（沿用 `docs/08` §2.1）：
> **無聊 = 玩家已經知道怎麼做。**
> 新系統的准入標準是——*它是否製造了一個玩家必須重新設計產線的新問題？*
> 只是加數字、加產量、加內容量的一律不列。

## 1. 先講結論：三個結構性風險（這比「下一步做什麼」更急）

### 風險 A（最嚴重）：存在一條「不蓋工廠」的主導策略

把 `GameData.CoinValue` 的售價與配方輸入交叉比對，會得到一張很難看的表格：

| 產物 | 輸入市價總和 | 產出市價 | 淨變化 |
| --- | --- | --- | --- |
| 鐵板 | 鐵礦 6 | 20 | **+233%** |
| 銅板 | 銅礦 8 | 26 | **+225%** |
| 鈦板 | 鈦礦 30 | 95 | +217% |
| 矽晶圓 | 矽礦 14 | 46 | +229% |
| 晶體 | 晶石 48 | 135 | +181% |
| 金板 | 金礦 62 | 170 | +174% |
| 星核晶 | 星核礦 140 | 430 | +207% |
| 電路 | 銅板×2 = 52 | 70 | +35% |
| 高級電路 | 電路 70 + 晶圓 46 = 116 | 240 | +107% |
| **齒輪** | 鐵板×3 = 60 | 45 | **−25%** |
| **科研包** | 齒輪 45 + 電路 70 = 115 | 90 | **−22%** |
| **砲彈×2** | 齒輪 45 + 銅板 26 = 71 | 36 | **−49%** |
| **穿甲彈×2** | 砲彈 18 + 晶體 135 = 153 | 132 | **−14%** |

規律非常乾淨：**熔煉（1 進 1 出）全部暴利；組裝（多進 1 出）大部分虧損。**

這導出一個玩家可以自己發現、而且發現後就沒有理由放棄的最適解：

> **礦機 + 熔煉爐 + 賣板。組裝機只做「自己要用」的最低量，其他全部不要蓋。**

而「自己要用」的量極低（科研包只為了研究、砲彈只為了防守），所以**整條組裝鏈從資產變成稅負**。這正是第一原則定義的「玩家已經知道怎麼做」——而且是**最壞的一種**：最適解是「蓋最少的工廠」。

### 風險 B：星球階梯在 30–60 分鐘內會被走完

以熔煉賣板估算：1 台熔煉爐 ≈ 20 金幣 / 1.8 秒 ≈ **11 金幣/秒**；10 台 ≈ 111 金幣/秒 ≈ **6,660 金幣/分鐘**。
全部星球門檻合計 $8k + $25k + $70k + $180k = **$283,000**，在 10 台熔煉爐規模下約 **45 分鐘**走完；到深淵零號後礦價再 ×3.2，更快。

也就是說：**五顆星球不是五個階段，是四十五分鐘。** 而且星球之間的差異（日照、天氣、蟲池）雖然存在，但經濟誘因只是「一樣的事、賣更貴」——建造 ×1.8 的成本倍率完全壓不住礦價 ×3.2 的收益倍率。

### 風險 C：中後期沒有「問題」，只有「規模」

- 研究是純 +6% 數值 → 沒有質變，沒有「解鎖後要重畫產線」的時刻
- 威脅規模上限 64 隻（且 >50 隻尋路會變笨）→ 防禦有硬性天花板，後期只會越來越安全
- 教學 14 步完成後目標面板消失 → 玩家失去方向，只剩「產線變大」

**這三個風險是 §3 所有建議的前提。風險 A 不修，做任何經濟系統都是蓋在沙上。**

## 3. 逐條詳述

### R1 · 價值鏈反轉修正

- **一句話概念**：把 22 種物品的售價重算一遍，讓「加工深度」永遠是正收益，並幫沒有去路的物品（鈦板、金板、星核晶、石頭）接上配方。
- **它製造的新問題**：這條本身**不製造新問題**——它是修復項。但它拔掉了目前的主導策略（風險 A）。在「賣板最賺」成立的情況下，R3／R4／R13 全部會失效，因為玩家對任何經濟誘因的最適回應都是同一句：「那我還是蓋熔煉爐」。
- **MDA 與心流**：
  - **M（機制）**：售價表、配方表。
  - **D（動態）**：目前是「深度加工 = 懲罰」，玩家的動態是「盡量不要加工」。修正後變成「每多一層加工 = 一次產線投資決策」。
  - **A（美學）**：目前是 *Submission（消極接受）*；修正後才有 *Discovery* 與 *Expression*。
  - **心流／勝任感**：主導策略會讓挑戰曲線塌陷——玩家找到最適解後技巧不再成長，直接掉出心流通道。這是「勝任感」最典型的殺手。
- **玩法影響**：立刻讓組裝鏈從「稅」變回「資產」；讓後期星球的高價礦有理由留在本地加工再賣。
- **具體修法建議**（全部在 `core.json` 可覆蓋的範圍內，或 `CoreTypes.DefaultAssemblerRecipes`）：
  1. 定價公式化：讓每個產物的售價 ≥ 輸入市價總和 × 1.15（加工溢價），再乘上「配方秒數」的時間價值。
  2. 鈦板／金板／星核晶目前是**終端物品、零配方**（`grep` 已確認：只出現在售價表與熔煉配方）。各給 1–2 個配方，讓後期星球有自己的加工鏈，而不只是「更貴的礦」。
  3. 石頭（2 金幣）目前是純雜質，會污染礦機產出 → 給它一個用途（建材／路基）或從礦池移除。
- **成本**：**低**。幾乎全是數值與 JSON，1 小時內可完成並用 `tools/Bench` 驗證。
- **依賴**：無。但要動 `GameData`（已在 `game2d/src/Core` 分叉，不會影響 3D 版）。
- **風險**：改售價會連帶影響「星球門檻 vs. 收入曲線」的平衡（見風險 B）。建議 R1 與 R3 同批上線，一次調到位，不要分兩次調。

---

### R2 · 分流器／過濾器／溢出閘

- **一句話概念**：加入三種「物流控制」建築——`Splitter`（輪流分流）、`Filter`（只讓指定物品通過）、`OverflowGate`（主線滿了才溢出）。
- **它製造的新問題**：**「這一條帶子上混了兩種東西，我要怎麼把它們分開？」** 以及「多餘的產能要送去哪裡？」
- **MDA 與心流**：
  - **M**：三種新建築 + 帶上物品的路由規則。
  - **D**：玩家的動態從「把 A 接到 B」升級成「設計一張流量圖」——這正是自動化品類的核心動詞。沒有分流器，玩家的產線只能是**一對一鏈條**；有了分流器，產線才第一次變成**網路**。
  - **A**：*Expression（表達）* 與 *Discovery*。這是目前版本缺口最大的一塊美學。
  - **心流／勝任感**：分流器把「產線變大」這個單調的量化成長，換成「產線變複雜」的質化成長 → 技巧與挑戰同步上升，心流通道得以延長。
- **玩法影響**：這是**槓桿最高的一條**。它本身成本中等，但它是 R3（多產品輪替）、R4（訂單切換）、R11（品質路由）、R13（跨星分貨）的共同前提。沒有它，這些建議的解法空間會縮水一半。
- **成本**：**中**。Core 要加建築種類與帶上路由邏輯；渲染層要 3 個新精靈與方向箭頭。可沿用既有 `MarkTileChanged` 索引機制。
- **依賴**：`BuildingKind` 擴充；`core.json` 的 `costs` / `powerDemand` 加欄位；圖鑑與教學要補。
- **風險**：
  1. 帶上物品目前的模型是「每格 8 槽的鏈結串列」，分流要處理「某槽被取走後的中間空洞」——邊界情況多（見「邊緣情況」）。
  2. UI 認知負荷：過濾器要能「點選物品」設定，2D 面板空間有限。**建議先只做 Splitter + OverflowGate，Filter 放第二批**，避免一次塞三種新概念。

---

### R3 · 市場飽和與動態需求 ★ 第一原則最佳

- **一句話概念**：每一種物品各有獨立的「市場存量」——你賣越多，它的單價越低；不賣就隨時間回升。系統每週期隨機指定 1–2 種「熱門商品」漲價。
- **它製造的新問題**：**「我這條產線的產品正在把自己做賤，我要換做什麼？」**
- **為什麼這是第一原則的最佳解**（詳見 §7）：它讓「產線變大」這一個已知解法**從內部自我失效**。不是靠外部隨機事件打斷你，而是經濟本身告訴你：你越擅長做 X，X 就越不值錢。這逼出的不是「忍受」，而是真正的「重新設計」。
- **MDA 與心流**：
  - **M**：每物品一個 `Saturation` 值（賣出 +、隨時間 −），單價 = 基準價 × `f(Saturation)` × 星球倍率；加上週期性熱門商品。
  - **D**：玩家的動態從「最大化單一產品產量」變成**「維持產品組合的多樣性」**。工廠從一條大產線，變成**多條小產線的投資組合**——這是一個本質不同的問題類型。
  - **A**：*Challenge*（每週期重新盤點）+ *Fellowship*（若未來有排行榜，不同玩家的產品組合會分歧）。
  - **心流／勝任感**：它提供**週期性的挑戰重置**。玩家剛把鐵板產線調到最佳 → 鐵板飽和 → 技巧與挑戰重新對齊 → 心流再次發生。這是自決論中「勝任感」的標準餵法：*每次征服後立刻給一個新的可征服目標*。
- **玩法影響**：直接治好風險 A 與風險 B。星球階梯不再只靠「礦價更高」，因為任何單一礦都會飽和。
- **成本**：**中**。Core 加一個 per-item 飽和陣列與時間回復；UI 要在交易面板顯示「鐵板：單價 18（飽和 62%，每分鐘回升 4%）」。
- **依賴**：**R1**（先修定價，否則飽和機制會把玩家推向更極端的「只賣最賺的那一個」）；**強烈建議搭配 R2**（分流器讓「換產品」變成可設計的解法，而不是拆掉整條線重建）。
- **風險**：
  1. **認知過載**：22 種物品各自的飽和度是很大的資訊量。**緩解**：交易面板只列出「你有庫存的物品」，並用顏色標示「飽和／正常／熱門」三態。
  2. **懲罰感**：如果玩家覺得「我變強了但收入沒變多」會很挫折。**緩解**：飽和只影響**該物品**，總收入仍隨產品多樣性上升（多樣化 = 變強的正當出口）。
  3. 存檔要新增欄位（v8），注意版本遷移。

### R4 · 委託合約（限時訂單）

- **一句話概念**：系統定期給出「120 秒內交付 60 個高級電路，報酬 3 倍市價 + 聲望」的訂單，玩家需要把貨送進指定的出口建築。
- **它製造的新問題**：**「我要不要為這張訂單，暫時把產線改去做別的東西？」** 這是一個**排程問題**，而不是產量問題。
- **MDA 與心流**：
  - **M**：訂單表（物品／數量／時限／報酬倍率）＋交付判定。
  - **D**：玩家面前出現**機會成本**——接單要犧牲既有產線的產出，不接則損失報酬。這是自動化遊戲很少處理、但極適合「小型基地」規模的決策類型。
  - **A**：*Challenge* + *Narrative*（訂單可以有委託方：殖民地／商會／軍方，給世界觀最低成本的存在感）。
  - **心流／勝任感**：**明確、短週期、可判定的目標**——這是自決論裡勝任感最強的餵法（比「無限研究」強得多，因為研究的反馈是模糊的 +6%）。
- **玩法影響**：**中期節奏斷層的直接解法之一**（見 §4）。它給 10–30 分鐘這段「教學結束、還沒到下一顆星球」的空窗期一個具體目標。
- **成本**：**低**。純 Core 邏輯 + 一個 UI 面板；不需要新美術（可沿用既有物品圖示）。
- **依賴**：若要有「暫時改產線」的解法深度，最好有 **R2**（分流器）；但只用「手動切配方 + 拉一條臨時帶子」也能成立，所以可獨立上線。
- **風險**：
  1. 訂單若太簡單（「交 20 個鐵板」）→ 淪為按鈕領獎。**緩解**：訂單需求要**對準玩家目前的瓶頸**（例如要求「兩種物品同時交付」或「高階物品」，迫使改線）。
  2. 時限壓力可能與「放鬆建造」的基調衝突。**建議做成可選**（設定裡可關，或做成「商會聲望」支線）。

### R5 · 危機事件系統（週期性規則變動）

- **一句話概念**：每 5–8 分鐘觸發一次事件，臨時改一條世界規則：離子風暴延長、礦脈暫時貧化、蟲潮提前、某種建築停擺、市場某類商品崩盤。
- **它製造的新問題**：**「這 3 分鐘的規則不一樣了，我的產線撐得住嗎？」**
- **MDA 與心流**：
  - **M**：事件表（`id` / 預告秒數 / 持續秒數 / 影響的參數 / 解除條件）＋預告 UI。
  - **D**：這就是**「週期性切換問題類型」最字面的實現**。玩家的動態從「優化」切換成「應變」——兩種完全不同的認知模式交替出現，正是對抗單調的最直接手段。
  - **A**：*Sensation*（警報、音樂切換）+ *Challenge*。
  - **心流／勝任感**：事件是**外部施加的挑戰增量**，把玩家從「技巧 > 挑戰」的無聊區推回心流通道。關鍵是預告（見風險）。
- **玩法影響**：讓「掛機等研究」變成不可能；也讓天氣系統從「被動承受」變成「可準備的」。
- **成本**：**中**。系統本身不貴（一個事件調度器 + 參數修飾層）；貴的是**每個事件的內容**。建議首批只做 6–8 種事件。
- **依賴**：事件的參數修飾層要能碰到電力／天氣／市場／蟲潮，所以需要這些系統有**統一的修飾介面**——這是這條建議真正的工程價值（見 §5）。
- **風險**：
  1. **隨機懲罰感**：無預警的負面事件會被讀成「遊戲在整我」。**強制設計**：所有事件必須有 30–60 秒預告 + 明確的倒數 UI + 可執行的對策（例如「關掉非必要機器省電」）。
  2. 事件若只是「數值變差」會很無聊。**設計紅線**：每個事件必須改變**最適解**，而不是讓所有做法一起變差。

### R6 · 礦脈枯竭與再勘探

- **一句話概念**：單一礦脈被連續開採後產量遞減（例如累積產出超過門檻後降到 40%，最終 15%），逼玩家往外找新礦區。
- **它製造的新問題**：**「我的工廠要開始搬家了——新礦區離這裡 200 格，物流要怎麼接？」**
- **MDA 與心流**：
  - **M**：礦脈累積產出計數 → 產量係數；地圖上標示未開採礦區。
  - **D**：這是自動化遊戲裡最經典的**中期轉折**：從「在一個地方優化」變成「管理多個地點」。它第一次讓「無限地圖」產生意義（目前無限地圖只是技術成就，沒有玩法動機）。
  - **A**：*Discovery*（勘探）+ *Challenge*（擴張）。
  - **心流／勝任感**：強制性的階段轉換，避免玩家在單一基地裡無限精修而技巧停滯。
- **玩法影響**：**中期節奏斷層的第二個直接解法**（見 §4）。它把 20–40 分鐘這段「基地已經穩定」的時期變成一個新的擴張期。
- **成本**：**中**。Core 加礦脈計數；渲染層要在地圖上顯示枯竭程度；**與 R14（遠距物流）有天然銜接**，但要小心兩者同時上線會一次塞太多。
- **依賴**：小地圖要能顯示枯竭度；若要「搬家」，藍圖系統（CFBP1）就是玩家的解法工具——已經有了，很好。
- **風險**：
  1. **懲罰感最強的一條**。玩家投入 30 分鐘的產線被迫廢棄，很容易被讀成懲罰。**緩解**：(a) 枯竭到 15% 就停，不要歸零；(b) 枯竭速度要慢到「一代基地约 30–45 分鐘才需要擴張」；(c) 藍圖讓重建很便宜（已有）；(d) 提供「修復／增產」的研究線作為另一條出路。
  2. 若同時上線 R14（軌道），會一次引入兩個大系統 → 建議 R6 先上，R14 後上。

### R7 · 地形空間約束

- **一句話概念**：加入不可建造的地形（裂谷／岩漿裂隙／冰湖／隕石坑），並讓部分建築需要「地基」才能蓋在上面。
- **它製造的新問題**：**「產線的形狀第一次變成一道題目。」** 目前 2D 地形只有明暗差異，任何地方都能蓋 → 空間是免費的。
- **MDA 與心流**：
  - **M**：地形新增「不可建造」標記；建築放置規則加上地形檢查。
  - **D**：空間從「無限免費資源」變成「稀缺約束」。玩家的動態從「照最優模板鋪」變成**「為這塊地形解一道 packing 謎題」**。這是**唯一一條會讓玩家的既有藍圖模板局部失效的建議**——而「模板失效」正是第一原則想要的。
  - **A**：*Expression* + *Challenge*。
  - **心流／勝任感**：空間謎題是自動化遊戲中技巧上限最高的子技巧之一（參見 Factorio 的「壓縮產線」社群），能提供長期勝任感。
- **玩法影響**：小而深。它不需要新物品、不需要新數值，卻讓「每顆星球的地形」第一次有玩法意義（配合你未來要加的更多星球）。
- **成本**：**中**。地形生成要加約束層（純函式，不影響存檔）、放置檢查、小地圖圖例、以及**每顆星球不同的障礙密度**。
- **依賴**：`Terrain` 是 seed 純函式 → 加約束層**不會破壞既有存檔**（地形不存檔，重算即可）。這點非常好。
- **風險**：
  1. 玩家會覺得「這只是擋路」而不是「這是有趣的約束」。**設計紅線**：障礙要**成片、有規則**（例如裂谷是長條狀），不要隨機撒點——有規則的障礙才能被「設計」，隨機的障礙只會被「繞過」。
  2. 與既有建築的碰撞：`OccupiedNear()` 邏輯要一起改。

### R8 · 區域電網與斷路器

- **一句話概念**：電網不再全局連通——相鄰建築自動連成一個網，玩家可以放「斷路器」分割網域，並設定每個網域的供電優先級。
- **它製造的新問題**：**「電不夠的時候，先斷誰？」** 目前電力不足只是「全廠效率一起下降」，玩家沒有決策可做；切成區域後，這變成一個**資源分配的取捨題**（斷熔煉保砲塔？斷研究保採礦？）。
- **MDA 與心流**：
  - **M**：電力連通性計算（並查集或每 tick 的網域掃描）+ 斷路器建築 + 優先級設定。
  - **D**：玩家的動態從「蓋更多發電機」這個單一解法，變成**「供電拓撲設計」**。而且它與 R9（斷電型威脅）形成漂亮的雙人組：威脅會打電網 → 玩家要設計冗餘。
  - **A**：*Challenge* + *Expression*。
  - **心流／勝任感**：這是一個「你有明確工具、但沒有標準答案」的問題 → 高度勝任感。
- **玩法影響**：讓電力系統從「數值條」變成「拓撲題」。也讓天氣（太陽能歸零）從「大家一起變慢」變成「你的網域切得對不對」。
- **成本**：**中～高**。電力結算是每 tick 全廠掃描，切成網域後要重新設計這段（效能要重跑 `tools/Bench`）。
- **依賴**：需要電力系統重構；建議**與 R9 同批**（否則區域電網沒有被威脅的意義）。
- **風險**：**效能**。若每 tick 重算連通性，大型工廠會爆。建議做成「建築放置／拆除時增量更新網域」，不是每 tick 重算。

### R9 · 威脅行為標籤化

- **一句話概念**：把蟲種從「數值不同」升級成「行為不同」——資料表給每種蟲一個行為標籤：`Biter`（咬建築）／`Sapper`（優先咬電纜／發電）／`Flyer`（無視防線直取產線）／`EMP`（癱瘓範圍內砲塔）／`Burrow`（鑽地出現在基地內部）。
- **它製造的新問題**：**「我的防線要防的是哪一種破壞？」** 目前 10 種蟲的解法全是同一個（更多砲塔）——這是「已知解法」最純粹的樣子。
- **MDA 與心流**：
  - **M**：`AlienKind` 加 `Behavior` 欄位；AI 分支。
  - **D**：玩家的動態從「把砲塔圍一圈」變成**「針對威脅組合設計防禦布局」**：飛行蟲要內部防空、EMP 要分散砲塔、鑽地要預留內圈。防禦第一次有**多種正確答案**。
  - **A**：*Challenge* + *Discovery*。
  - **心流／勝任感**：每種新蟲種 = 一次「既有防線失效」的事件 = 心流重置。而且**這剛好對接你「未來會加更多蟲種」的方向**（見 §5）。
- **玩法影響**：讓 10 種蟲從「10 種數值」變成「10 種問題」。也解除風險 C 的「威脅天花板」——因為威脅的強度不再只靠數量（目前上限 64 隻）。
- **成本**：**中**。每種行為是一個小 AI 分支；`Flyer` 最便宜（改尋路目標），`EMP`／`Burrow` 較貴。
- **依賴**：`AlienKind` 擴充；`PlanetDef.AlienPool` 已經存在，正好可以讓每顆星球有不同的威脅組合（已有基礎設施，很省）。
- **風險**：
  1. 行為太多會認知過載。**建議首批只做 3 種行為**（`Flyer` / `Sapper` / `EMP`），剩下的蟲種沿用 `Biter`。
  2. **公平性**：鑽地與飛行會讓玩家覺得「圍一圈也沒用」→ 挫折。**緩解**：一定要有可見的預警（地圖上顯示來襲方向與種類）與明確的反制建築。

### R10 · 科技樹質變

- **一句話概念**：研究不再只有 4 條 +6% 的數值線，加入**會解鎖新機制的里程碑**（解鎖分流器、解鎖模組插槽、解鎖第二種彈藥、解鎖軌道）。
- **它製造的新問題**：**「解鎖之後，我的產線要重畫。」** 這是「縱向數值」轉「橫向內容」的轉換器。
- **MDA 與心流**：
  - **M**：研究線從 `int[4]` 擴充為「數值線 + 里程碑線」；里程碑有一次性解鎖效果。
  - **D**：目前研究的動態是純累積（永遠 +6%，永遠不改變做法）。加入里程碑後，研究變成**週期性的問題切換器**——每解鎖一次就重畫產線一次。這直接對接第一原則。
  - **A**：*Discovery*（解鎖的驚喜）+ *Expression*。
  - **心流／勝任感**：里程碑給出**不連續的成就節點**。無限研究只有「永遠還有下一級」，里程碑給「我到了一個新階段」——後者的勝任感強得多。
- **玩法影響**：讓「無限研究」這個已經很不錯的留存機制，從「數值牆」變成「內容牆」。
- **成本**：**中**。研究資料要表驅動化；里程碑的效果內容才是成本（每一個里程碑都是一個小功能）。
- **依賴**：里程碑的內容多半來自其他建議（R2 分流器、R12 模組、R14 軌道）→ **這條建議真正的角色是「把其他建議包成研究獎勵」**，是排程工具而非獨立功能。
- **風險**：成本 ×1.6 遞增非常陡（第 15 級累積約 38,400 科研包）。里程碑若放在高等級，玩家一輩子看不到。**建議里程碑放在第 3／5／8／12 級**，確保前 30 分鐘就能拿到 2 個。

### R11 · 品質／純度分流

- **一句話概念**：礦脈有「純度」，純度決定產物品質（粗糙／標準／精良），高品質料走獨立產線可以做出高品質成品（賣價倍率高、或用於特殊配方）。
- **它製造的新問題**：**「高品質的料要不要走獨立產線？」** 這會製造自動化遊戲中最深的設計問題之一：如何在同一條物流網裡分離並路由多種品質。
- **MDA 與心流**：
  - **M**：物品帶品質標記；帶上物品變成 `id + quality`；配方有品質繼承規則；過濾器可按品質過濾。
  - **D**：這會讓**整張物流圖的複雜度翻倍**，而且要玩家重新學一套規則 → 是「已知解法失效」最徹底的一條。
  - **A**：*Discovery* + *Expression*（優化空間極大，社群會自己長出設計）。
  - **心流／勝任感**：技巧天花板最高的建議，長期勝任感最強。
- **玩法影響**：直接解決風險 C 的「後期只剩規模」——後期變成「品質路由優化」，這是一個幾乎無底的問題空間。
- **成本**：**高**。`BeltTile` 與 `Building` 的物品欄位要從 `ItemId` 擴充成「id + 品質」，這會碰到模擬核心最熱的程式碼路徑；效能要重跑壓測；UI 要能分辨品質。
- **依賴**：**R2（過濾器）是硬性前提**；建議 R1、R2、R3 都上線後再考慮。
- **風險**：
  1. **認知過載最大**的一條。對休閒玩家可能太難。**緩解**：品質做成**可選規則**（新遊戲時可勾選），或只在後期星球出現。
  2. 效能：物品結構變大會直接衝擊 0.7 ms/tick 的漂亮數字。
  3. 存檔版本與藍圖格式（CFBP1）都要升級。

### R12 · 建築模組插槽

- **一句話概念**：熔煉爐／組裝機可以有 2 個模組槽，插入「產量 +30%」「耗電 −20%」「速度 +25% 但產廢料」等模組，模組本身也是要生產的物品。
- **它製造的新問題**：**「我要蓋更多棟，還是把這棟塞滿？」** 這是一個**空間 vs. 效能的取捨**，而且答案會隨地形（R7）與電力（R8）而變。
- **MDA 與心流**：
  - **M**：建築加模組陣列；模組是物品，要生產、要送上產線（用執行器／帶子裝配）。
  - **D**：把「擴張」這個單一動詞，拆成「擴張」與「深化」兩個互相競爭的動詞。競爭 = 決策 = 不無聊。
  - **A**：*Expression*。
  - **心流／勝任感**：提供「在同一個建築上持續投入」的長期目標，勝任感來自配置的精修。
- **玩法影響**：讓後期不再是「複製貼上 50 台熔煉爐」，而是「這 10 台各有不同配置」。
- **成本**：**中**。建築資料加欄位；模組物品的生產與裝配流程；UI 要能檢視／更換模組。
- **依賴**：需要一個「把物品送進建築而非帶上」的裝配機制（可沿用砲塔補彈的現成邏輯，成本因此降低）。
- **風險**：模組若都是純數值 +%，會淪為「另一種研究」→ 違反第一原則。**設計紅線**：模組必須有**副作用**（例如「加速但多耗電」「增產但產廢料需要處理」），有副作用才有取捨。

### R13 · 跨星球物流

- **一句話概念**：傳送門不只能換地圖，還能**運貨**——A 星生產的東西可以送到 B 星賣；每顆星球的市場飽和度與熱門商品各自獨立。
- **它製造的新問題**：**「在哪裡生產、在哪裡賣、運輸瓶頸在哪？」** 這是一個**跨地點的供應鏈問題**，比單基地產線高一個維度。
- **MDA 與心流**：
  - **M**：傳送門貨運介面（輸入帶 → 輸出帶）、吞吐量限制、跨星市場狀態。
  - **D**：玩家的動態從「管理一座工廠」變成**「管理一個帝國」**。而且它立刻讓「五顆星球」從「五個難度等級」變成「五個互相依存的經濟區」——這是風險 B 的最佳解藥。
  - **A**：*Expression* + *Challenge*。
  - **心流／勝任感**：規模感的飛躍（從基地到帝國），是長期遊玩最強的情緒回報之一。
- **玩法影響**：把目前「換星球 = 重開一局」的體驗，變成「換星球 = 擴張版圖」。這也是 5 顆星球的投資第一次真正被兌現。
- **成本**：**高**。跨星存檔（每顆星球一個 `SimWorld`？還是共享 Hub？）、UI 的跨星視圖、吞吐量平衡。
- **依賴**：**R3（市場飽和）**——沒有飽和機制的話，跨星套利會退化成「全部送到最貴的那顆星賣」的單一解。也要先確定傳送門的存檔結構。
- **風險**：
  1. 這是**架構層級**的建議，可能要動 `SimWorld` 的生命週期與存檔格式（目前 `PlanetIndex` 是單一值）。**建議先做一個技術可行性評估**再排程。
  2. 認知過載：同時管理 5 顆星球會讓 UI 變得非常重。

### R14 · 遠距物流（軌道／無人機）+ 距離梯度資源

- **一句話概念**：加入長距離運輸形態（軌道車／無人機），並讓越遠的區域有越好的礦脈（距離梯度）。
- **它製造的新問題**：**「集中生產 vs. 分散生產？」** 以及「這個礦這麼遠，值得為它拉一條軌道嗎？」
- **MDA 與心流**：
  - **M**：軌道／無人機建築、裝卸站、距離梯度礦脈豐富度。
  - **D**：它給「無限地圖」一個真正的動機（目前無限地圖沒有玩法動機，見 `docs/06` 問題 12）。玩家的動態從「在原地長大」變成**「決定工廠的地理結構」**。
  - **A**：*Discovery* + *Expression*。
  - **心流／勝任感**：與 R6（礦脈枯竭）天然銜接——枯竭逼你往外走，遠距物流給你往外走的工具。
- **玩法影響**：這是自動化遊戲後期的標準第二幕（「產線」→「物流網」），也是目前版本最明顯的缺失（只有傳送帶一種物流形態）。
- **成本**：**高**。軌道要有尋路／調度；無人機要有飛行與指派；兩者都要大量新美術與 UI。
- **依賴**：**建議排在 R6 之後**（先有「往外走」的壓力，再有「往外走」的工具，順序反了工具會沒人用）。
- **風險**：
  1. 成本最高的兩條之一（與 R13 並列）。若資源有限，優先做「無人機」（比軌道簡單，且 2D 俯視角表現直覺）。
  2. 與 `SimWorld.Key` 的 ±32760 邊界無關（那是 65k × 65k，夠大了），但要確認串流效能。

## 4. 中期節奏斷層專章（10–30 分鐘發生什麼事）

### 斷層是怎麼形成的

| 時間 | 玩家在做什麼 | 遊戲給的目標 |
| --- | --- | --- |
| 0–10 分 | 教學 14 步，學會全套閉環 | 目標面板（明確） |
| **10–30 分** | **擴產線 → 賣 → 存錢開傳送門** | **目標面板已隱藏（教學完成）** ❌ |
| 30–60 分 | 走完 5 顆星球階梯 | 只剩「下一顆星球」 |
| 60 分+ | 產線變大、研究 +6% | 無 |

**核心問題**：10–30 分鐘這段，玩家的決策只有「蓋更多一樣的東西」。這正是第一原則定義的無聊。

### 三個解法（建議三者選二，不要一次全上）

| 解法 | 斷層怎麼被補 | 為什麼有效 | 建議順位 |
| --- | --- | --- | --- |
| **R4 委託合約** | 每 2–3 分鐘一個明確、可判定的小目標 | 直接補上「目標面板消失」造成的方向真空；成本最低 | **第一順位** |
| **R5 危機事件** | 每 5–8 分鐘一次規則變動，強制重新盤點 | 週期性切換問題類型；打斷「自動駕駛」狀態 | **第二順位** |
| **R6 礦脈枯竭** | 20–40 分鐘製造一次「必須擴張」的轉折 | 把中期變成一個新的擴張期；但它本身也需要 R14 配套 | 第三順位（成本較高） |

**我的建議**：**R4 + R5 同批上線**，作為「v0.3.0 中期節奏包」。兩者都是資料表驅動、都不需要新美術、都能獨立驗證，加起來的成本低於任何一條大型建議。R6 留到下一批。

### 一個幾乎零成本的額外解法

> **把目標面板改成「常駐目標軌道」，不要隨著教學完成而隱藏。**
>
> 教學 14 步完成後，接上第二串「階段目標」（例如「累積 $8,000 開傳送門」「研究任一線達到 5 級」「單一波次擋下 30 隻蟲」「在霜蝕四號蓋出第一條晶體產線」）。
> 成本：近乎零（沿用現成的 `_objectivePanel` 與 `Objective` 結構，加一串資料）。
> 效果：這是最便宜的「給沒目標的玩家一個推力」，與 `docs/05` 的 M10 設計意圖完全一致。

## 5. 資料表驅動：哪些建議讓「未來加內容」更輕鬆

你已確認的方向是**持續加更多星球、更多蟲種、更多建築與礦物**。以下是「投資一次、之後每次加內容都變便宜」的建議：

### 高槓桿（讓未來擴充變便宜）

| 建議 | 對未來擴充的效益 |
| --- | --- |
| **R9 威脅行為標籤化** | ★★★★★ 加新蟲種時，只需要填「數值 + 行為標籤」，不用寫新 AI。10 種蟲從 10 份特製程式變成 10 行資料。 |
| **R5 危機事件系統** | ★★★★★ 事件表建立後，**每一個未來加的星球／天氣／蟲種，都能自動成為新事件的素材**。這是一台「把內容轉成問題」的機器。 |
| **R10 科技樹質變** | ★★★★☆ 把研究資料表化後，新機制可以用「加一個里程碑」的方式上架，不用改研究系統本身。 |
| **R7 地形空間約束** | ★★★★☆ 地形約束是 seed 純函式 → **加新星球時只要填一組地形參數，就自動得到一種新的空間謎題**。 |
| **R1 價值鏈修正** | ★★★★☆ 若改成「售價由公式從配方自動推導」，未來**加新物品/新配方時不必手動定價**，也就不會再出現價值倒掛。 |

### 建議同時做的基礎建設（不屬於 14 條，但很划算）

1. **配方與售價的「自動定價器」**：寫一個小工具，從配方樹自動算出建議售價（輸入市價 × 加工溢價 × 時間成本），每次加內容時跑一次，作為人工調整的基準線。這能**永久免疫風險 A 復發**。
2. **平衡檢查腳本**：在 `SelfTest2D` 加一組「經濟健全性測試」——斷言「任何產物的售價 ≥ 輸入總和 × 1.15」「任何物品至少有一個配方去路或一個用途」。每次加內容自動跑，倒掛當場被抓到。
3. **把 `PlanetDef` 搬進 `core.json`**：目前 5 顆星球是寫死在 `Noise.cs` 的 C# 欄位。搬到 JSON 後，加星球不用重新編譯，也讓玩家／模組作者能加星球（對接 `docs/05` 的「資料表 + 藍圖 UGC」方向）。

## 7. 最符合第一設計原則的一條

> # 🏆 R3 · 市場飽和與動態需求

**理由**：

1. **它讓已知解法從內部自我失效。** 不是靠外部事件打斷你，而是經濟本身告訴你：「你越擅長做 X，X 就越不值錢。」玩家對此的回應不可能是「忍受」或「撐過去」，只能是**真的去設計另一條產線**。這正是准入標準問的那句話。
2. **它自帶週期性，不需要外部排程。** 飽和 → 收入下降 → 換產品 → 舊產品回升 → 再飽和。這是一個**從系統內部長出來的換題節奏**，比任何定時器都更自然、更難被玩家預測性地繞過。
3. **它把「產線變大」這個唯一的成長向量，換成「產品組合多樣化」。** 成長向量從一維變成多維——這是最結構性的「問題類型切換」。
4. **它一次治好兩個風險**：風險 A（組裝虧錢，因為飽和讓「只熔煉不組裝」也被懲罰）與風險 B（星球階梯太便宜，因為任何單一礦都會飽和）。

**亞軍**：**R5 危機事件系統**（「週期性切換問題類型」最字面的實現）與 **R11 品質分流**（技巧天花板最高）。
**但請注意**：R3 與 R5 建議**同批上線**——R3 提供結構性的長期換題，R5 提供短期的節奏打點，兩者互補且共用同一套「參數修飾層」基礎設施。

## 8. 建議「不要做」的清單

沿用 `docs/05` 的判斷依據（① 是否服務於無限可玩；② 是否服務於低配可跑），以下**明確建議不做**：

| 不要做 | 原因 |
| --- | --- |
| 更多「+X% 產量」的研究線 | 這就是風險 C 的成因。研究要走 R10 的質變路線，不是加更多數值線。 |
| 更多「只是更貴的礦」的星球 | 這是風險 B 的成因。新星球必須帶來**新的空間約束（R7）／新的威脅組合（R9）／新的市場區位（R13）**，不能只有 `PriceMultiplier` 更高。 |
| 玩家等級／裝備／屬性成長 | `docs/05` 已決策：玩家變強只能靠工廠。 |
| 即時多人聯機 | 已決策（D3）。 |
| 腳本級 Mod 系統 | 已決策改走資料表 + 藍圖 UGC。 |
| 需要微操的戰鬥 | 戰鬥必須自動化、可預算。 |
